Yang ditanya saat demo & batas ruang lingkup

OTP tidak sampai ke inbox

Konfigurasi bawaan mengirim email ke berkas log. Fungsinya jalan, tapi saat demo kode verifikasi harus dibaca dari storage/logs atau SMTP diisi dulu.

Mock masih default aktif

AppConfig.useMock bernilai true secara bawaan. Saat demo, jalankan dengan --dart-define=USE_MOCK=false --dart-define=API_BASE_URL=http://<tunnel>/api. Tanpa flag itu, semua tombol order menjawab dari data lokal dan tidak menyentuh backend sama sekali.

FCM adalah modul paling berisiko

FCM masuk daftar 3 API wajib dan dosen biasanya meminta melihatnya. Sisi HP sudah lengkap (firebase_messaging aktif, token dikirim ke server lewat PATCH /api/fcm-token), dan pengirimnya sudah nyata — app/Services/FcmService.php + FcmFake masuk develop lewat merge d85aae8, satu titik panggil per transisi di ServiceStatusLogObserver. Yang belum ada: FCM_CREDENTIALS di server dan admin belum punya pusat notifikasi, jadi kiriman ke mitra hanya sampai di HP. Saat demo, sampaikan bedanya — kode dan testnya selesai, kredensialnya belum dipasang.

Belum ada pembayaran asli

Tidak ada gateway QRIS maupun webhook. Pembayaran hanya mencatat status di database. Sampaikan sebagai batas ruang lingkup, bukan fitur yang gagal.

Kenapa OTP lewat email (biaya dan kemudahan deploy), kenapa kolom dokumen nullable (null berarti belum diunggah, lebih jujur daripada teks palsu), dan kenapa chat dalam aplikasi ditunda (tabel messages baru direncanakan).
